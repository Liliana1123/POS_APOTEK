🔑 Primary Key

  • Semua tabel: id (BIGINT auto-increment)
  • no_faktur — unique (penerimaan & penjualan)
  • barcode — unique (barang)
  • member_id — unique (format MBR-XXXXXX)

🔗 Foreign Key

  • cascadeOnDelete: detail_penerimaan, detail_penjualan, discount_usage
  • setNull/delete: user_id di activity_logs

📦 Batch System

  • FEFO ordering: expired_date ASC
  • Index: ['barang_id', 'expired_date']
  • Stok = jumlah - (terjual + rusak)

Activity Diagram — Proses Transaksi Penjualan

Alur kasir memproses transaksi dari scan barang hingga cetak struk. Validasi stok dilakukan via lockForUpdate() sebelum data disimpan. Semua dijalankan dalam satu DB::transaction().

    H -->|Tidak| I[Pilih Pelanggan]

    L --> M
    M --> Q{Input uang pembayaran}

✅ Validasi

  • Stok per batch: lockForUpdate() sebelum simpan
  • FEFO: expired_date ASC diproses duluan
  • Diskon gabungan cap max 50%
  • Uang harus ≥ grand total

💾 Database

  • DB::transaction() — rollback otomatis jika stok kurang
  • lockForUpdate() — prevent race condition
  • decrement stok per batch, set aktif=false jika habis

📋 Audit Trail

  • ActivityLog: "Transaksi Penjualan"
  • DiscountUsage: catat diskon member & custom per item
  • Export CSV tersedia di semua halaman laporan
